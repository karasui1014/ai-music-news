# AI音楽ニュース

AI音楽まわりの最新ニュースを自動で集めて、スマホで読みやすく並べるツールです。

- **28か所のRSS**（Googleニュース／海外メディア／日本語メディア／AI各社の公式ブログ）から自動収集
- AI音楽に関係する記事だけを選び、同じ記事の重複はまとめる
- **海外の記事は見出しも要約も自動で日本語に翻訳**（原文も小さく併記）
- GitHub にのせれば、**1日4回、勝手に最新化**（Macの電源が入っていなくてもOK）
- スマホ表示前提のデザイン。ホーム画面に追加でアプリのように使える
- 「あとで読む」保存、既読の色分け、キーワード検索、ダーク／ライト切り替え

---

## ファイル構成

| ファイル | 役割 |
|---|---|
| `collect.mjs` | ニュースを集めて `data/news.json` を作る本体（Node.js） |
| `translate.mjs` | 英語の見出し・要約を日本語にする処理 |
| `feeds.json` | **取得元の設定**。増やす・減らすときはここを編集 |
| `data/news.json` | 集めた記事データ。自動生成されるので直接編集しない |
| `index.html` / `style.css` / `app.js` | 表示するページ |
| `sw.js` / `manifest.webmanifest` | ホーム画面追加・オフライン表示用 |
| `.github/workflows/update-news.yml` | GitHubで自動更新するための設定 |
| `ニュース更新.command` | ダブルクリックでニュースを集め直す |
| `ローカルで確認.command` | ダブルクリックでこのMacだけで表示を確認する |

## 1. まずMacで試す

1. `ニュース更新.command` をダブルクリック → 最新ニュースを集めます
2. `ローカルで確認.command` をダブルクリック → ブラウザで表示されます

> 初回に「開発元が未確認のため開けません」と出たら、そのファイルを **右クリック → 開く** を選び、確認ダイアログで「開く」を押してください。

Node.js が入っていない場合は [nodejs.org](https://nodejs.org/ja) からインストールしてください。

## 2. インターネットに公開して自動更新にする

ここまでやると、**カラスイさん以外の人も、いつでも最新の状態で読める**ようになります。

### ステップ1 — リポジトリを作る

1. GitHub にログインし、右上の **＋ → New repository**
2. リポジトリ名を決める（例: `ai-music-news`）
3. **Public** を選ぶ（Pagesを無料で使うため）
4. **Create repository**

### ステップ2 — ファイルをアップロードする

1. **uploading an existing file** をクリック
2. Finderで `AI音楽ニュース` フォルダを開き、**中身をすべて選んでドラッグ＆ドロップ**
   - `index.html` `style.css` `app.js` `sw.js` `collect.mjs` `translate.mjs` `feeds.json` `manifest.webmanifest` `README.md` `assets` フォルダ `data` フォルダ
3. 下の **Commit changes** を押す

### ステップ3 — 自動更新の設定ファイルを作る

`.github` は先頭がドットの隠しフォルダで、Finderからはドラッグしにくいので、GitHubの画面上で作ります。

1. リポジトリの **Add file → Create new file**
2. ファイル名の欄に、そのまま次を入力
   ```
   .github/workflows/update-news.yml
   ```
3. Macの `.github/workflows/update-news.yml` をテキストエディタで開き、**中身を全部コピーして貼り付け**
4. **Commit changes**

### ステップ4 — 自動更新に「書き込み許可」を与える

ここを忘れると自動更新が失敗します。

1. リポジトリの **Settings → Actions → General**
2. 一番下の **Workflow permissions**
3. **Read and write permissions** を選んで **Save**

### ステップ5 — ページを公開する

1. **Settings → Pages**
2. Source を **Deploy from a branch**
3. Branch を **main** ／ フォルダは **/ (root)** にして **Save**
4. 1〜2分待つと `https://（ユーザー名）.github.io/ai-music-news/` で開けます

### ステップ6 — 動作テスト

1. **Actions** タブ → 左の **ニュース自動更新** → 右の **Run workflow**
2. 緑のチェックが付けば成功です

以降は **日本時間の 6:00 / 12:00 / 18:00 / 22:00** に自動で更新されます。

> GitHubの定時実行は、混み具合によって数分〜十数分ずれることがあります。
> また、リポジトリを長期間まったく触らないと定時実行が止められることがあります。
> 止まっていたら **Run workflow** を一度押せば再開します。

### スマホのホーム画面に置く

- **iPhone（Safari）**: 共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**: 右上のメニュー → 「ホーム画面に追加」

## 3. ニュース源を増やす・減らす

`feeds.json` の `sources` を編集します。

```json
{
  "id": "example",
  "name": "画面に出る名前",
  "url": "https://example.com/feed",
  "category": "jp",
  "filter": "keyword",
  "lang": "ja",
  "enabled": true
}
```

- `category` … `jp`（日本語） / `global`（海外） / `official`（AI各社公式） / `youtube`（動画）
- `filter` … 記事の絞り込み方
  | 値 | 意味 | 向いている媒体 |
  |---|---|---|
  | `all` | 全部取り込む | 検索条件自体が絞り込みになっているフィード |
  | `ai` | 見出しにAI関連の語があれば取り込む | 音楽専門メディア |
  | `music` | 見出しに音楽関連の語があれば取り込む | AI専門メディア |
  | `keyword` | 見出しにAIと音楽の語が**両方**必要 | 総合ニュースサイト |
- `enabled` … `false` にすると一時的に止められます

編集したら `ニュース更新.command` で結果を確認してください。取得に失敗したフィードは
ページ下部の「取得元の状態を見る」で赤く表示されます。

### YouTubeチャンネルを追加する

1. 追加したいチャンネルのページを開く
2. ページを右クリック →「ページのソースを表示」
3. `channelId` で検索し、`UC` で始まる24文字のIDを見つける
4. `feeds.json` の YouTube の項目を書き換える

```json
{
  "id": "youtube-suno",
  "name": "Suno公式チャンネル",
  "url": "https://www.youtube.com/feeds/videos.xml?channel_id=UCxxxxxxxxxxxxxxxxxxxxxx",
  "category": "youtube",
  "filter": "all",
  "lang": "en",
  "enabled": true
}
```

## 4. 日本語への翻訳について

海外メディアの記事は、収集と同時に見出しと要約を日本語にしています。
カードでは**日本語が主役**で、その下に小さく原文の見出しを添えています（翻訳が怪しいときの確認用）。

**使っている翻訳サービス**（どちらもAPIキーの登録は不要）

1. **MyMemory** … 公式API。無料枠は1日5,000語
2. **Google翻訳（非公式エンドポイント）** … 1つ目が使えないときの予備

片方が止まっても、もう片方に自動で切り替わります。両方だめだった記事は原文のまま表示されます。

**一度訳した記事は記録され、二度と翻訳し直しません。** そのため毎回の通信量はごくわずかで、
無料枠を使い切る心配はほとんどありません（1回の実行で最大70件まで）。

> Google側は非公式の経路なので、将来止まる可能性があります。
> 止まってもMyMemory側が動き続けるので、表示が壊れることはありません。

**翻訳量を増やしたいとき（任意）**

MyMemory はメールアドレスを添えると上限が 1日5,000語 → 50,000語 に増えます。
メールアドレスをリポジトリに直接書くと迷惑メールの的になるので、GitHubのSecretsに入れます。

1. **Settings → Secrets and variables → Actions → New repository secret**
2. Name に `MYMEMORY_EMAIL`、Secret にメールアドレスを入れて保存

設定しなくてもそのまま動きます。

## 5. セキュリティ対策

外部のサイトが書いた文章をそのまま表示するツールなので、次の対策を入れています。

**表示ページ側**

- **CSP（Content Security Policy）** を設定し、外部スクリプト・外部画像・外部通信をすべて禁止。インラインスクリプトも実行できません
- 記事の見出しや説明文を **HTMLとして解釈しない**（`innerHTML` を一切使わず `textContent` のみ）。これによりXSS（悪意あるスクリプトの混入）を防いでいます
- リンクは **`http` / `https` のURLだけ許可**。`javascript:` などは表示前に弾きます
- 外部リンクには `rel="noopener noreferrer"` と `referrer: no-referrer` を付け、リンク先に元ページを操作されたり、閲覧元を知られたりしないようにしています
- 外部CDN・外部フォント・アクセス解析は**一切読み込みません**
- 保存するのは記事IDと表示テーマだけ。個人情報は扱わず、外部に送信もしません

**収集スクリプト側**

- 取得先は `http` / `https` のみ。タイムアウト15秒、1件あたり最大5MBの上限つき
- 取り込んだ文字列からHTMLタグを除去し、長さを制限してから保存
- 外部ライブラリを一切使わない（依存パッケージ経由の乗っ取りリスクを避けるため）

**GitHub Actions側**

- 権限は `contents: write` のみ（自分のリポジトリへの書き込みだけ）
- APIキーやトークンの登録は不要。翻訳もキーなしで動くので、秘密情報を持ちません
- 同時実行を禁止し、20分でタイムアウト

## 6. 困ったとき

**ページは開くが記事が出ない**
`data/news.json` がアップロードされているか確認してください。ファイルを直接ダブルクリックして開いた場合も表示されません（`ローカルで確認.command` を使ってください）。

**自動更新されない**
Actionsタブでエラーを確認します。`Permission denied` と出ていたら、上の **ステップ4** の書き込み許可が抜けています。

**特定の媒体が出てこない**
ページ下部の「取得元の状態を見る」で赤くなっていれば、その媒体のRSSが移転・終了しています。`feeds.json` のURLを直すか `enabled: false` にしてください。

**関係ない記事が混ざる／欲しい記事が出ない**
`feeds.json` のその媒体の `filter` を調整してください（`keyword` が一番厳しく、`all` が一番ゆるい）。

**ページを直したのに画面が変わらない**
オフライン表示用のキャッシュが残っています。**もう一度リロード**すれば新しくなります
（1回目のリロードで裏側が入れ替わり、2回目で画面に出る仕組みです）。
すぐ反映したいときは Mac なら **Command + Shift + R**、iPhone なら一度ページを閉じて開き直してください。

**海外記事が英語のまま出ている**
その記事は翻訳に失敗しています（翻訳サービスの一時的な不調か、1回あたりの上限70件を超えた分）。
次回の更新で自動的に訳されるので、そのまま置いておいて大丈夫です。
`ニュース更新.command` の実行結果に「訳せた記事 ◯件」と出るので、そこで状況が分かります。
